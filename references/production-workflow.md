# 成片制作流程

## 1. 选择实现路径

先检查目标环境：

- 已有 Remotion 或其他可重复渲染的视频工程：沿用其组件、字体、字幕和渲染入口。
- 已有本 Skill 对应的配置入口：优先复制一份 episode 配置，不直接改历史成片数据。
- 没有视频工程：在用户指定工作区创建隔离工程，不把一次性依赖和生成物塞进无关业务目录。

不要依赖最初抽离本 Skill 的项目路径、内部模块名或私有媒体。所有输入都应来自当前任务、当前仓库或用户明确提供的来源。

## 2. 素材采集

为每项素材保存：本地文件、原始 URL、采集时间、原始尺寸/时长、使用镜头、来源类型、授权备注。

来源类型决定画面角标：官方、自有产品实录、示意、媒体报道。对比镜头左右两侧来源不同时（例如左边是示意，右边是官方界面），两侧分别标注，不能让示意图借用官方角标。

质量优先级：

1. 官方提供的原始 4K/1080p 视频或原图。
2. 官方网页在高设备像素比下的完整截图或元素截图。
3. 官方社交账号的原始媒体。
4. 只有信息价值、没有合格视觉质量的资料，改成引用文字或重新设计信息图，不放大低清图。

截图前关闭个人账号信息、通知、书签、密钥和其他隐私内容。网页截图必须忠实于真实页面；装饰性重绘不能伪装成产品界面。

手机小窗观看时整页截图只剩纹理。需要观众读出内容的地方，截取对应局部（一张卡片、一段原句、一张架构图），按 16:9 高分辨率导出。

## 3. 从内容映射到镜头

| 段落 | 运动语义 | 画面重点 | 常见错误 |
|---|---|---|---|
| 定义 | cursor-flyover | 一份真实官方页面或产品画面被镜头发现并聚焦 | 光标乱跑、主体太小 |
| 对比 | before-after-slider-scrub | 同一任务两种方式的直接差异 | 比较对象不一致、标签太抽象 |
| 场景 | deck-deal-flyin | 2–3 张卡依次落位，每张只讲一个场景 | 卡片太多、全部同时发光 |
| 核心能力 | ai-stream-response | 输入、判断和可继续使用的结果形成清楚因果 | 伪造终端、代码太小 |
| 边界 | card-flip-reveal | 限制逐项揭示，最终形成完整判断 | 把限制藏在小字里 |
| 落点 | text-column-converge | 多个日常入口汇聚到一个核心能力 | 结尾堆满口号和 CTA |

| 证据特写 | focus-zoom | 全景停一拍后 6 帧急推到目标区域，轻微回弹，框出并标注 | 目标框太小导致放大过头发糊；落在字幕带里 |
| 证据标注 | scan-annotate | 扫描线匀速下扫，扫过区域下缘后才弹框和中文标注 | 先弹框后扫描；标注写英文原词不翻译 |

两张证据卡需要 `focusRegions`（按 16:9 画面的百分比坐标）。急推会把区域放大到约占画面 65%：区域越小倍数越大，素材宽度要不小于 1920×放大倍数，否则特写发糊；框大一点（约 35%）用 2 倍截图就够。整画面急推全片不超过 3 处。

卡名只约束运动逻辑。字体、颜色、间距、材质和字幕样式应来自目标产品或本期视觉方向，不能直接套用另一品牌的皮肤。

每个镜头只安排一个主要动作。关键信息落定后预留阅读和呼吸时间；不要用连续转场掩盖信息不足。

## 4. 画面与字幕

字幕按真实配音对齐：配音后逐镜转写取得每个字的时间，按拼音把时间对回口播原文，每句字幕在它被说出时出现；强调词在字幕里用强调色标出，文字本身不变。没有转写工具时才退回按句子平均分配时长。


- 输出 1920×1080 时，源素材尽量不低于画面中实际占用尺寸。
- 横版会在竖屏手机里缩小约 5 倍：标题不小于 60px，字幕不小于 60px，正文最小 32px 且只做补充。必须读懂的信息放进标题或字幕。
- 使用安全边距，避免平台 UI 遮挡标题和字幕。
- 字幕按意义断句，不按固定字符数机械切割。
- 一屏突出一个核心判断；正文、证据标签和来源角标必须有清楚层级。
- 官方素材应带简短来源标签，但不要让 URL 占据主要画面。
- `shotCopy` 只服务画面短标签，不应悄悄改变口播事实。

## 5. 配音和声音

1. 先锁定最终口播，再生成配音。配音前先出静帧确认画面。
2. 为品牌名、缩写和多音字建立发音表。
3. 逐段测量真实音频时长，根据停顿和语义调整镜头，不拉伸语音凑时长。
4. 字幕从最终口播生成，并与对应音频绑定。
5. 0 秒就要有声音：人声直接开口，并在第一帧配一个短提示音；开头无声是 2 秒内划走的常见原因。其余 SFX 只强调关键动作：进入、比较切换、结果落定、边界翻面、结尾收束。
6. 有 BGM 时让人声始终清晰；音乐不能替代叙事节奏。

如果 TTS 不支持发音字典，优先改写为自然且不会误读的等价表达；不要把错误读音留给后期侥幸修复。

为每段配音记录指纹（口播、语气、发音规则、音色与合成参数）。只重新合成指纹变化的镜头；复用时指纹不一致就报错，避免新字幕配旧声音。

渲染后把成片响度统一到 -16 LUFS、真峰值 -1.5 dBTP（两遍 loudnorm，视频流直接复制）。再逐镜转写配音，用不带声调的拼音和口播比对，列出需要试听的地方；只差声调的误读和多音字转写查不出，仍要试听。某一镜有杂音或读错时，只重配那一镜。

## 6. 确定性时间线

- 所有时间都以帧或由帧推导的秒数表示。
- 伪随机粒子、抖动和散布使用固定种子。
- 不在渲染逻辑中使用 `Date.now()` 或无种子的 `Math.random()`。
- 音频更新后重新计算场景起止、字幕和转场位置。
- 同一输入重复渲染应得到一致的画面和时长。

## 7. 渲染与迭代

先渲静帧（不配音、按估算时长），再渲低成本预览，最后渲高质量成片：

1. 每个镜头至少检查开头、信息落定和结尾三个时间点。
2. 抽取全片等间隔帧做蒙太奇，检查视觉连续性和重复构图。
3. 用最终音轨渲染预览并完整播放。
4. 修正后重新执行同样检查；不要只看被修改的局部。
5. 最终导出优先 1920×1080、30fps、H.264 CRF 14–18，并保留无损或高质量中间资产。

如果使用上游 `video-shotcraft` 的代码、音效或组件，先核对其许可证和具体资源声明；仅使用卡名和运动语义不等于已经使用了它的准确实现。
