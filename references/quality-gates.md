# 交付质量门槛

## 事实与文案

- 每个产品能力、数字、日期和限制都有可追溯来源。
- 没有把预测、愿景或演示结果写成已经普遍可用的事实。
- 普通观众无需预先理解模型、推理、代理或 API 才能听懂主线。
- 第一帧已经出现本期核心判断，前 2 秒口播说出来，0 秒有声音；开头没有黑屏、模糊、空画面、自我介绍或系列介绍。
- 封面：3:4 和 4:3 各一张，底图清晰明亮、只有一个视觉重点；封面文案不超过 10 个字、每行不超过 5 个字（英文单词算 1 个，标点不算），与标题互补不重复。
- 至少有一处主动解释边界，不把产品塑造成万能工具。
- 标题、封面、口播和画面表达的是同一件事。

## 素材与画面

- 所有官方截图和视频都来自记录过的网址，文件可定位。
- 最终画面没有低清放大、压缩马赛克、错误裁切或加载失败占位图。
- 所有小字在 1920×1080 的实际输出中可读。
- 产品真实界面与示意动画有明确区分：每个真实画面的角标写明来源类型，示意画面标“示意”。
- 把总览图缩到约 640px 宽（相当于手机竖屏里的横版小窗）检查：标题和字幕都读得出来。
- 字体、颜色和 UI 风格统一，不带入上一期产品的品牌痕迹。
- 关键画面停留足够长，观众能读完而不是只看到闪过。
- 没有密钥、客户数据、个人信息、内部链接或浏览器隐私信息。

## 动效与时间线

- 每个镜头只有一个主要运动意图。
- 转场发生在语义节点，不会截断口播或字幕。
- 元素没有越界、闪烁、穿帮、错误遮挡或最后一帧跳变。
- 随机效果使用固定种子；重复渲染结果稳定。
- 素材短于镜头时有明确处理，不会突然黑屏或卡死。

## 配音、字幕与声音

- 品牌、人名、缩写、数字和多音字已逐项听检。
- 字幕文本与最终配音一致，没有旧稿残留。
- 字幕出现和消失跟随语义，不提前泄露整段内容。
- 人声清楚，没有削波、底噪突变或左右声道异常。
- BGM 和 SFX 不盖住人声；静音段也经过检查。
- 视频总时长、音轨时长和结尾收束一致。
- 复用的配音与当前口播逐字一致（有配音指纹记录可查）。
- 成片响度约 -16 LUFS、真峰值不超过 -1.5 dBTP；配音核对报告里标出的每一处都已试听。

## 审美自检（判例式）

以下条目改编自 video-shotcraft 的审美准则（Apache-2.0），带 * 的由渲染脚本自动检查并写入 `-checks.md`：

- R1*：关键信息落定后至少停留 1 秒（30 帧）再切镜。
- R2：飞入、批量入场用非线性缓动和越来越快的节拍，任何元素都不做匀速直线运动（扫描线这类“机械视线”除外）。
- R3：节奏宁慢勿快；模拟操作按真人速度，观众能跟着做一遍。
- R4*：整画面冲击（急推、震屏、闪帧）全片不超过 3 处，只给最重要的证据。
- Q1：表现既有页面一律用真实截图，示意画面标“示意”。
- Q2*：放大镜头的素材宽度不小于显示宽度（1920×放大倍数），放大走布局尺寸而不是 transform 缩放。
- C1*：字幕每秒不超过 8 个字，手机小窗读得完。

## 必做终检

1. 在最终分辨率下检查每个镜头的关键静帧。
2. 从最终 MP4 抽取音轨，检查波形、时长和峰值。
3. 从头到尾完整播放一次最终 MP4，不能用编辑器预览代替。
4. 让一个没有参与制作的人或独立上下文，根据原始需求和来源清单复核事实、可懂度、画质、发音和节奏。
5. 对发现的问题重新渲染后，再完整播放新文件。

## 交付报告

简要写明：

- 成片路径、分辨率、帧率、时长和编码。
- 封面（3:4 与 4:3）、脚本、来源清单和各平台发布文案路径。
- 已验证的发音规则。
- 已知限制，以及仍需用户确认的版权或事实项。
- 实际执行过的 QA，不把“应该没问题”写成已验证。
